# Automated Marketer
Turn an approved product position into relevant public conversation candidates and individual reply drafts. Read [references/workflow.md](references/workflow.md), [references/lead-schema.md](references/lead-schema.md), and [references/reply-patterns.md](references/reply-patterns.md). These references make this skill self-contained.

## Work
1. Read the user's product facts, audience, supported claims, next-step link and exclusions. If not supplied, build a concise provisional brief from authorized sources and mark assumptions. Check the tools actually available and the user's research budget.
2. Before browser research, select the user's connected browser/profile using [references/browser-session.md](references/browser-session.md); prefer their existing Chrome session over an isolated agent browser unless they chose another browser. Search using problem + task + intent + alternative phrases. Read whole threads and current community rules. Access public material through supported search/browser/API tools, respecting terms, rate limits, account permissions and access controls. A search result is not a verified prospect.
3. Keep candidates only when the visible conversation supports a concrete product fit. Cite the permalink and a concise excerpt/paraphrase. Record what the person actually says; do not infer income, identity, private contact details or buying authority. No mass profiling or unsolicited DMs.
4. Use the batch targets and rolling draft workflow in the workflow reference. Score with the schema; rules and safety of an external action are gates, not points to buy your way past. Save deduplicated `leads.csv`, reply drafts, and a research log. A useful review draft can be saved while posting/prior-contact/rules checks are pending, with its publication hold explicit. The optional `scripts/campaign_tools.py` ranks an existing CSV and makes UTM links without network access; inspect `--help` first. Its stricter `draft-ready` output is a preflight state based on supplied fields, not a requirement to write review drafts. It does not find or contact people.
5. Draft useful answers for the strongest eligible conversations. Record what existing comments already cover, any author follow-up, and the useful point your answer adds. Give an immediately usable step, explain your product connection honestly, and include a product link when directly relevant and allowed. Assess direct-link and profile routes for strong fits instead of defaulting the entire campaign to no-link advice; do not force a promotional quota. Use the patterns as structure, not copy/paste scripts. No fake customer stories, urgency, votes or identical replies across threads.
6. For batches, generate and open an individual browser review queue using [references/review-queue.md](references/review-queue.md). Put long reports/CSV in supporting records. If requested, prepare native Reddit composers for the user's own Post click, preserving any existing text and leaving submission to them. End with concise review instructions and actual execution status. The normal stopping point is a draft queue. “Help me market this” is not blanket permission to post or message people.

## If publishing is explicitly requested
Recheck the latest instruction, exact approved text, destination, account, affiliation, current rules, thread status and actual tool/platform permission immediately before posting. A prior specific authorization remains valid within its scope; do not invent extra approval steps. If one requirement is missing, keep the draft and explain the missing item. Post only within authorized scope. Save the returned permalink/receipt and actual time; uncertain outcomes are “unknown”, not success. Before retrying an uncertain publish, inspect the destination to avoid duplicates. Stop on a denial, removal, rate limit, changed rules or user HOLD. Never bypass restrictions or shift accounts to continue.

A skill cannot schedule background work. If asked to repeat later, use an actually available scheduling feature with authorized scope, or provide a repeatable session plan and state that no schedule was created.

## Existing session and link discipline
Public research and draft completion do not require a new Reddit account. Reuse legitimately available existing sessions/tools within scope. If the user wants posting but has no account/session, provide the official Reddit signup/sign-in steps in [references/reddit-account-setup.md](references/reddit-account-setup.md), let the user complete credentials, verification and CAPTCHA, and resume the authorized task when the session is available. Do not request their password or claim automatic login. If posting remains unavailable, hand off ready-to-paste drafts and original thread links and report “not posted”. For every reply choose direct link, honest profile reference, no product mention or skip. Profile promotion obeys the same rules as a direct link and must never bypass a restriction. Keep the useful answer specific; no forced slang, fake customer persona or invented personal experience.

## Handoff status
Use `DRAFT` for review text with pending checks, `READY` for a completed review artifact, and `LIVE / VERIFIED` only for an actual publication supported by a permalink and visible/API evidence. Hand the queue to the owner for review or an already authorized publication step; do not infer posting permission from a local Keep decision.
