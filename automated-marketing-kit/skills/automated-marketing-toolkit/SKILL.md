# Automated Marketing Kit — start the campaign here
Run the user's marketing workflow from product understanding to a reviewed conversation queue. Read [references/product-and-offer.md](references/product-and-offer.md), [references/conversation-launch.md](references/conversation-launch.md), [references/reply-and-publishing.md](references/reply-and-publishing.md), and [assets/campaign-handoff.md](assets/campaign-handoff.md) as each phase needs it. All required guidance is included in this skill; other installed toolkit skills are optional deeper specialists.

Before any browser work, including the initial product-site review, read [references/browser-session.md](references/browser-session.md) and select the user's connected browser/profile. Prefer their existing Chrome session over an isolated agent browser unless they chose another browser. Record the selected session and reuse it throughout the run.

## 1. Understand what is being sold
Recover facts from the current conversation, supplied brief and approved product sources before interviewing. Ask a small batch of decisive questions only: who uses it, what they can do today, the repeated problem, what they use instead, actual price/stage, important limits and the real next-step URL. If a repository is available, inspect relevant user flows read-only; distinguish source findings from tested behavior. Do not inspect keys, private customer data or unrelated files. Produce a product truth card and evidence gaps.

## 2. Choose an ICP, USP and offer
Define the ICP as role + situation + urgent job, with disqualifiers. Define the USP as a supported difference relative to what that buyer actually does today, not “AI-powered”. State exactly what is available for the actual price and the useful result it can support. Match claims to evidence. Select one initial audience/angle, explain the tradeoff and record limits. Continue within the user's authorized research/draft task; pause only if a missing fact prevents an honest next step.

## 3. Build a top-10 launch shortlist
Start from the [ten named starter communities](references/top-10-starter-communities.md), then find up to ten communities that discuss this job, including niche buyer communities rather than only founder forums. Explain fit, cite live examples and verify the current rules for the actual proposed action. Ten is a maximum, not a quota. A public community directory is a starting point, not permission or promised reach. If browsing is absent, return exact searches and work from supplied public threads without pretending a live check occurred.

## 4. Find and qualify high-intent conversations
Run the batch workflow in [references/conversation-launch.md](references/conversation-launch.md). For a normal first pass, aim to collect 20–40 distinct post examples across 3–6 relevant communities, then read the strongest candidates and produce 6–10 useful review drafts where evidence supports them. Adapt to the user's scope and available results; these are working targets, not quotas. Recover the existing brief instead of repeating onboarding. Use native question/help filters where they improve results. Screen obvious poor fits from discovery cards; read the full post and relevant replies before drafting. Save the first few drafts while continuing discovery instead of spending the whole run on one thread or a polished strategy report.

Search for active requests, specific workaround frustration and alternatives being considered. Exclude already-solved, closed, stale-for-participation, irrelevant or unsupported-use-case threads unless there is a specific unanswered point worth contributing. Save URLs, short evidence, actual request, product-fit reason, limitation, rule status and score. Distinguish discovered examples, inspected conversations and actual draft candidates. Do not infer private identity, income or buying authority. Never fill a quota with weak matches.

## 5. Draft replies people can use
Answer the actual question with a concrete step, decision criterion or appropriate workaround. Record what existing comments already cover, any author follow-up, and the useful point your answer adds. Use the user's real voice or clear plain language. No forced slang, fabricated experience, customer impersonation, canned praise or repeated pitch. Choose direct link / honest profile reference / no product mention / skip using the publishing reference. Assess commercial routes deliberately; do not default every strong, permitted product fit to a no-link answer. Product recommendations disclose the user's real affiliation. A profile pointer is still promotion and cannot bypass a link or self-promotion rule.

Drafting is the authorized work, not a request for publication. Missing posting approval, account/prior-contact checks or an unavailable rules page can hold publication without stopping a useful review draft based on a fully read conversation. Label each unresolved check; never mark it ready to post. Do not draft an advertisement prohibited by known rules; use a useful no-mention answer or skip. Keep contribution drafts separate from product-recommendation candidates and do not call every example a buyer lead.

For a batch handoff, use [references/review-queue.md](references/review-queue.md) to generate and open a browser review page with individual posts and editable comments. Reports and CSV are supporting records. If the user asks to review native tabs and click Post themselves, prepare the native composers within that scope and leave submission to them; copying or filling never counts as publication.

## 6. Publish only when both scope and access permit
Reuse existing authenticated sessions or legitimately configured tools. Public research and draft completion need no account. When the user requests posting without an account/session, follow [references/reddit-account-setup.md](references/reddit-account-setup.md): provide the official Reddit signup/sign-in steps, let the user complete credentials, verification and CAPTCHA, then resume within the existing authorization. Do not request passwords, invent auto-login or pretend you have a connector. If authorized posting is possible in the present session, recheck latest user steering, exact scope, text/destination, rules, thread status and prior replies; publish only within that scope and save the actual receipt/permalink. Do not ask for repeated approval of an action already specifically authorized. If scope or access is missing, hand over ready drafts and direct thread links, clearly stating that nothing was posted. Never switch accounts, evade blocks or repeatedly retry an uncertain mutation.

## Completion
Open the browser reply queue as the primary batch review handoff. Keep the product truth card, ICP/USP/offer, shortlist, qualified conversation table and skipped-thread reasons in supporting records. Return a concise execution status and review instructions. Show “researched”, “drafted”, “published with permalink” or “not posted” accurately. No claim that traffic, customers, rankings or a background monitor exist without evidence or an actual supported process.

## Handoff status
Use `DRAFT` for review text with pending checks, `READY` for a completed review artifact, and `LIVE / VERIFIED` only for an actual publication supported by a permalink and visible/API evidence. Hand the queue to the owner for review or an already authorized publication step; do not infer posting permission from a local Keep decision.
