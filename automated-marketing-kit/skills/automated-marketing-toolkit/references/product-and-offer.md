# Product understanding → ICP → USP → offer
## Reuse known context
Use what the user already told you. Avoid a long intake when their repo or website can answer the question. A concise initial question batch is useful only for gaps that change fit or claims: current usable workflow, buyer, repeated incident, workaround, price/stage and important limits.

## Read-only repository trace
Read project guidance, route/entrypoint and owning UI/service/types for the relevant user task. Check what data enters, what the product does, what output it produces and what prerequisites it has. A named integration or README claim is not proof it works. Record relevant paths, observed implementation and untested assumptions. Do not edit source, run migrations, read secrets or access private customer records for a marketing brief.

## Product truth card
Product; stage; user; task; supported mechanism; output; prerequisite; limitation; price/billing; public next-step URL; affiliation; claim/source/date; observed/tested/supplied/inferred status.

## Pick a buying situation
Example: “operations lead at a five-person agency whose client approvals get lost in email” is testable. “businesses wanting AI” is not. Name the trigger, consequence, current workaround, buyer constraints and what disqualifies someone. Do not infer demographic or sensitive attributes from public profiles.

## Make the difference concrete
Compare with the actual manual or product alternative. State one capability that changes this task, how it changes it and where the alternative is still better. If the difference is unproven, call it a hypothesis and design a small research test. No unsupported “only tool”, universal time-saving or guaranteed customer result.

## Offer boundaries
Actual deliverable/access, price and billing, current availability, setup, proof, next step, support/refund terms only if provided. Research/positioning is not permission to change the live price, guarantee, checkout or product. Use one clear audience/angle for the initial campaign and retain a concise claim ledger.
