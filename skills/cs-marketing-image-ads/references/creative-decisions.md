# Creative decisions from practical revisions

These are reusable examples, not fixed offers, brand rules or performance claims.
Use the current user's audience, destination and supplied references.

## Sell the next action

| Destination | Useful ad promise | Common mismatch |
|---|---|---|
| Free webinar | “Learn how to build an app you can actually launch” + “Watch the free class” | Selling a software licence without explaining why to watch |
| Paid case study | The specific method demonstrated + its actual price | Implying the inexpensive lesson includes done-for-you implementation |
| Product trial | A capability the user can actually try | Borrowing an unrelated founder revenue result as a guarantee |

For a pain ad, specificity is stronger than shouting. “AI fixes one thing and
breaks another?” names a familiar event. “Improve your workflow” does not.
The supporting line must advance from the pain to a useful reason to click.

## Make the image carry the meaning

| Hook | Visual that explains it | Visual failure |
|---|---|---|
| Fixing more than building | Short AI correction history beside the product breaking after each change | A wall of arbitrary source code |
| Re-explaining every feature | Repeated requirements in successive chats and visibly drifting outputs | A tidy planning diagram with no visible repetition |
| App still cannot launch | One large build-error state the viewer can recognise immediately | Several tiny invented screens and an unreadable error |
| Rebuilding for every client | The same setup repeated across distinct client projects | Generic stressed person with no agent-building context |
| Maintaining an agent's memory | Linked notes, memory files and configuration in a plausible workspace | Glowing brain, neon network and imaginary warning labels |

Illustrative UI is a visual explanation, not evidence of an actual vendor defect
or a captured customer result. Use the user's real screenshot when that is the
requested source, and do not relabel generated UI as a real screenshot.

## Separate reference roles

- **Winning ad:** keep the aspects the user likes, such as a huge headline,
  simple face/object composition and high contrast. Replace the old offer.
- **Face:** identity and natural colour, not permission to distort anatomy or
  imply a testimonial the person did not give.
- **Software screenshot:** show the actual tool if requested; maintain legibility
  rather than squeezing every panel into a laptop screen.
- **Brand repo:** useful evidence, but a direct instruction rejecting its green
  palette in favour of a red/orange campaign reference takes precedence.

A cream footer is not universally good or bad. If a user rejects footer blocks,
integrate text into the main image. If they explicitly select a reference with
a cream band, preserve that deliberate choice. Do not resolve ambiguous taste
by repeatedly adding the same template.

## Revision discipline

“Keep ad 4's image, change the headline” means a local edit, not a new layout.
“13 looks the same as 11” needs a new composition, not a tint adjustment.
“Rename the six files” needs a directory check, collision-safe renaming and
verification, not another generation pass. A missing old version may mean the
user deliberately deleted it.

## Practical review cases

Before calling the packaged workflow proven, run it on a new campaign and record
the outputs. This skill remains draft. Review against these cases:

1. Given an accepted ad and one replacement headline, preserve all unrelated
   layout and imagery while spelling the supplied copy exactly.
2. Given a free webinar and a paid-case-study style reference, keep the visual
   style but remove the case-study price and unrelated revenue proof.
3. Given a current instruction to stop using green, do not reintroduce green
   from old CSS or a previous campaign brief.
4. Given a real terminal screenshot and “very little code”, make the familiar
   workspace recognisable without a code-heavy composition or fake screenshot claims.
5. Given a figure with duplicated limbs, correct and visually inspect anatomy
   before delivery. Do not rely on the prompt's anatomy instruction.

The workflow comes from multiple rounds of CodeSpring ad production and user
feedback. Accepted creative is usability evidence; it is not measured campaign
performance. No new image generation or independent campaign trial was performed
when packaging this first skill version.
